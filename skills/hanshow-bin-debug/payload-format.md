# Payload 格式

## 包序列

默认的 `.bin` 是所有 BLE 写入包首尾相连，中间没有分隔符：

```text
01 ff          清屏为全白（update_codex_payload.py --no-clear 时省略）
00 01 | 00 02  初始化：01 = BW 模式，02 = BWR 模式
04             准备 BW RAM
02 <≤200 字节> BW 平面数据，共 14 包（13×200 + 156）
05             准备红色 RAM（仅 BWR 模式）
02 <≤200 字节> 红色平面数据，共 14 包（仅 BWR 模式）
03             刷新显示（设备不回 ACK）
```

没有长度前缀也能切分，因为包长由命令字节决定：`00`/`01` 是 2 字节；`03`/`04`/`05` 是 1 字节；`02` 是 1 + min(200, 当前平面剩余字节数)。`update_codex_payload.py` 里的 `read_raw_packets` 就是按这个规则解析的。

`serialize.py --records` 生成的文件，每个包前面多一个 `uint16_le` 长度前缀。

## 位平面

- 分辨率 212x104，每个平面 212*104/8 = **2756 字节**。
- **按列优先**扫描：外层 x 从 0 到 211（从左到右），内层 y 从 0 到 103（从上到下）。每列正好 13 字节。
- 每个字节**高位在前**。
- BW 平面：1 = 白，0 = 黑。红色像素在 BW 平面里记为 0。
- 红色平面：1 = 红，0 = 不是红。
- 像素 (x, y) 的位置：bit 序号 `x*104 + y`，所在字节 `idx // 8`，掩码 `0x80 >> (idx % 8)`。

## 文件大小

| 模式 | 带清屏 | 不带清屏 |
|---|---|---|
| BW | 2776 | 2774 |
| BWR | 5547 | 5545 |
